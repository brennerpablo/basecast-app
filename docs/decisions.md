# Decisions — basecast-app

One line per decision: date, decision, reason. Cross-repo decisions live in `basecast-get-data`.

- 2026-09-26 — B0 copies only the Fundsys shell (layout, sidebar, theme, `components/ui`, the generic part of `components-app`), picked by following imports from each entry file, instead of copying the whole repo and deleting. — The Fundsys `src/` has ~5.4k files and its shell is tied to session, RBAC, Prisma and domain modules; the import closure keeps only what the app uses.
- 2026-09-26 — No login for now: only `ACCESS_MODE=public` (read-only demo) exists; the shell reads no session. — Judges must get in without friction; `login` mode comes later only if needed.
- 2026-09-26 — Next.js 16.3.6 instead of the 16.3.2 pinned in Fundsys. — 16.3.2 has two critical RCE advisories (GHSA-p293-qw3h-jr36, GHSA-2xp9-vwfh-vxw4); 16.3.6 is a patch bump.
- 2026-09-26 — `next.config` without `cacheComponents` / `partialPrefetching`. — Simpler for a small app: those require Suspense or `connection()` around every dynamic read. Can be turned on later.
- 2026-09-26 — Left out of the shell: app tab strip, ⌘K palette, notifications, audit, org switcher, user menu; the `Tabs` component keeps only `urlParam` (tab in the URL). — All coupled to Fundsys modules; not needed for the demo.
- 2026-09-26 — Dropped from `components-app`: `DataMatrixTable`, the compliance status badge, tag catalog, sub-actions and the risk/reference-series fields. — Domain or regulatory logic from Fundsys.
- 2026-09-26 — Neutral names for what carried the Fundsys brand: `--basecast-brand-*` CSS palette, `BRAND` tokens, `AppBadge` / `AppColoredBadge`, `basecast-theme` cookie. Emerald colors stay until the visual pass (B4). — No Fundsys branding in code; colors change later.
- 2026-09-26 — UI text in English with en-US dates; the Portuguese comments still in `components/ui`, `components-app` and `fields` get translated in a separate pass. — Agreed with the user to keep B0 fast.
- 2026-09-26 — `/` redirects to `/explorer` in `next.config` (307), not from a page. — A redirect page streams a 200 and only leaves on the client.
- 2026-09-26 — The brand kit lives unchanged in `docs/brand/`; the app serves only the "small" logo cut (light and dark) from `public/brand/`, cleaned: C2PA manifest removed, path coordinates rounded to 2 decimals, viewBox cropped to the drawing (26 KB → 8 KB each). The favicon is `src/app/icon.svg`, plus a full-bleed 180px `apple-icon.png`. — The full cut's ten thin strands fade below ~100px tall and no screen uses the standalone mark (the sidebar collapses offcanvas, not to icons).
- 2026-09-26 — The accent moves to the logo blue now instead of in B4: `#2F3FB8` in light; in dark the favicon's periwinkle `#8C9BFF` with navy ink `#141A4A`. Deep's surfaces move from a green cast (hue 150) to a navy one (hue 233). Emerald stays only where it means something (success badges, chart palettes, named color options). — Chosen by the user; a green-cast Deep under a blue accent would keep a piece of the old identity.
- 2026-09-26 — The product name reads "BaseCast" in user-facing text (tab title, image alt, README); package, repo and code names stay lowercase. — Matches the logo.
- 2026-09-26 — The palette is Base Power's, read from the `--bpc-color-*` tokens on basepowercompany.com (2026-09-26); this replaces the logo-blue accent above. Light: cream canvas `#f0eeeb`, white cards, text `#292826`, borders `#d8d7d5`. The brand splits the way Base's does: `--brand` is the FILL (lime `#b2dd79`, hover `#77a45a`) and `--basecast-brand-*` the INK (forest `#1e4d2b`) for text, links and tints. — Asked by the user; Base's own system separates brand-primary (fill) from text-brand (ink), and lime as text is 1.6:1 on white.
- 2026-09-26 — Two AA deviations from Base's pairings: the ink on the lime fill is green-100 `#102a17` instead of green-90 (green-90 on the hover fill is 3.4:1), and muted text is grey-80 `#54524f` instead of grey-60 (4.1:1 on white). — WCAG AA; both are still Base colors.
- 2026-09-26 — The sidebar is dark in every theme; in light it is Base's forest `#1e4d2b`. The app serves only the kit's dark logo (cream + lime), and the error pages show it on a `bg-sidebar` plate. — The kit's light logo is blue and clashes with Base's palette; the kit's own `dark-on-forest` render is this combination.
- 2026-09-26 — Deep becomes Base's forest (canvas and sidebar `#102a17`, card and borders stepped up in the same hue); Zinc stays neutral. Both dark themes use the lime fill and lime ink. — Base has no dark theme; chosen by the user.
- 2026-09-26 — The light sidebar goes back to the canvas cream `#f0eeeb` (hover grey-20 `#d8d7d5`, dark focus ring) instead of forest. Light themes show `public/brand/basecast-logo-small-green.svg`, the kit's light cut recolored to Base's greens (wordmark `#1e4d2b`, strands `#77a45a` → `#1e4d2b`); dark themes keep the kit's dark cut; the error pages drop the forest plate. This replaces the dark-sidebar line above. — The user did not like the forest sidebar. Of the three logos compared on cream (kit blue, recolored green, dark cut on a forest plate), the user picked the recolor.
- 2026-09-26 — Login (`ACCESS_MODE=login`) uses next-auth v4 like the Fundsys app (Credentials provider, JWT sessions, no adapter), not Auth.js v5. — Asked by the user; it is the code the Fundsys app already runs, and v4 supports Next 16.
- 2026-09-26 — Users sign in with email or username: an identifier with "@" is looked up as the email, otherwise as the username. Usernames cannot contain "@"; both are stored trimmed and lowercase. — Asked by the user; the identifier's shape picks the column without ambiguity.
- 2026-09-26 — Prisma comes back (7.x with `@prisma/adapter-pg`) only for the app's own tables; the kickoff had removed it because there was no database. Schema changes go through `prisma db push`, with no migration history, as in the Fundsys app. — The login users need a table; same stack as the Fundsys app.
- 2026-09-26 — The app connects to Cloud SQL (database `basecast`) as `postgres`, like the Fundsys app, but its tables live in their own schema `app`. — The connection was asked by the user. The schema keeps `db push` from ever seeing (and offering to drop) the pipelines' tables in `public`, and `basecast_reader` (the API) has no access to `app`, so password hashes stay out of the API's reach.
- 2026-09-26 — `ACCESS_MODE` unset, or anything other than `login`, means public, and public mode never touches the database (no session read, no Prisma query). — The judges' demo stays up even while the deployed app has no way into Cloud SQL.
- 2026-09-26 — Users are only created with `npm run user:create`, which reads the password from stdin and never overwrites an existing user. The first superadmin (`pablo`) got a password generated straight into Secret Manager (`app-superadmin-password`) and piped into the script. — No sign-up or admin screens are needed for the demo, and the password never shows in a terminal or a log.
- 2026-09-26 — Sign-in compares against a fixed dummy bcrypt hash when the user does not exist. — An unknown user takes as long to reject as a wrong password (~0.23 s each, measured), so response times do not reveal which accounts exist.
- 2026-09-26 — `overrides` pin `deepmerge-ts` ^8.0.2 and `mysql2` ^3.24.4. — Four high advisories reach the dev-only Prisma CLI through them; npm's suggested fix was downgrading to Prisma 6.
- 2026-09-26 — `.gitignore` ignores `/data/` (the repo root) instead of `data/`. — `data/` also matched `src/app/(app)/data/`, so the /data page had never been committed.
- 2026-09-26 — Production is on Vercel's personal scope (`brennerpablos-projects`) at `basecast.pbrenner.com`, with `ACCESS_MODE=login`; functions in `cle1`. — Asked by the user; the kickoff sets a personal Vercel account; `cle1` is the closest region to `us-central1`, as in the Fundsys app.
- 2026-09-26 — On Vercel the app reaches Cloud SQL through Google's Node connector (`@google-cloud/cloud-sql-connector`), as a dedicated service account `app-vercel` with only `roles/cloudsql.client`, whose JSON key lives in the Vercel env (`GCP_SA_KEY`). — The instance enforces connectors (no authorized networks) and Vercel cannot run the proxy. A key was faster to set up than Vercel OIDC + Workload Identity Federation, which is the upgrade path; the key alone cannot log in without the database password.
- 2026-09-26 — The first superadmin is renamed `pablo` → `admin` (same id and email) with a password the user chose, below the script's 12-character minimum; set with a one-off SQL update, not `user:create`. Secret Manager `app-superadmin-password` holds it as version 2 (version 1 disabled). — Asked by the user. The database is shared with production, so this login also works on the public URL; `isSuperAdmin` grants nothing extra in the app today.
- 2026-09-26 — Same-window tabs ported from fundsys-app: tab strip in the card's first row (desktop only), right-click menu on every shell link, pinned tabs, per-tab screen state (`useTabState`, used by `DataTable`), Back/Forward and pinned-tab divert through `src/instrumentation-client.ts`. Names and UI text translated to English. — Asked by the user; the feature was built and debugged in fundsys and upstate-ops.
- 2026-09-26 — `TabScreen` remounts the page on every tab switch (a `key` per tab, as in upstate-ops) instead of fundsys' keyless owner swap. — fundsys needs no key because `cacheComponents` keeps routes alive in `<Activity>`; basecast leaves it off, so without a key two tabs on the same path would share plain `useState`.
- 2026-09-26 — Left out of the port: the composed tab name ("Screen › Tab › Sub-tab"), the per-module icon registry, `chavesPorAba`, Home dashboard tabs, confidential-path rules and the org switch. The tab name is the pinned name, the last breadcrumb item or the `MAIN_MENU` label. — Screens are still placeholders with no sub-tabs; those pieces only pay off with fundsys' menus and modules.
- 2026-09-26 — Tests run on Node's `node:test` through `tsx`, with `jsdom` for DOM tests (`npm test`), the same setup as fundsys. — No runner existed; the store and link-rule tests come ported with the feature.
- 2026-09-26 — In login mode the tab lists are keyed by the user id (`public` in public mode), and sign-out clears the session list before `signOut`. — Two people on one browser must not share tabs or pinned tabs; pinned tabs stay in `localStorage` under their owner and come back when that user signs in.
- 2026-09-26 — All work happens on `main` in the three repos, with no feature branches or worktrees; the open branches (`b0-app-base`, `b1-auth`, `b2-tabs`) were folded into `main` and deleted. — Asked by the user: parallel branches and worktrees across several sessions cost rebases and blocked handoffs. Since a push to `main` deploys, checks run before every push.
- 2026-09-26 — `pbrenner.com` DNS moved from GoDaddy to Vercel's nameservers (`ns1/ns2.vercel-dns.com`), with the domain's Vercel DNS zone turned on (`zone: true`); the domain stays registered at GoDaddy. — Asked by the user: subdomains attached to a Vercel project now resolve with no manual record, so `basecast.pbrenner.com` works; the GoDaddy zone held only Vercel records (apex, `www`, `components`) and GoDaddy's `_domainconnect`, with no MX, TXT or DNSSEC to carry over.
- 2026-09-26 — `ACCESS_MODE` is gone and every page needs a session; this supersedes the public-mode decisions above (no login, "unset means public"). — Asked by the user; production already ran with `login`, and one mode means one code path in the proxy, the session helpers and the shell.
- 2026-09-26 — The sidebar footer is one user menu, as in the Fundsys app: the avatar (initials on the brand fill) and name open a menu with name and email, a Theme submenu and sign out; the standalone theme picker is gone. — Asked by the user; the `User` model has no picture field, so the avatar is initials only.
- 2026-09-26 — Email goes through Resend, on the personal Resend account the user already had, from `noreply@basecast.pbrenner.com`; the app's key (`basecast-app`, Secret Manager `app-resend-api-key`) is sending-only and restricted to the `basecast.pbrenner.com` domain. — Asked by the user; the Fundsys app already sends with Resend. A subdomain keeps BaseCast's sender reputation and key apart from the account's other domains, and the domain-restricted key cannot send as any of them.
- 2026-09-26 — `basecast.pbrenner.com` has an explicit CNAME to `cname.vercel-dns-017.com` in the Vercel zone, next to the Resend records (DKIM `resend._domainkey.basecast`, MX and SPF `send.basecast`, CNAME `rsend.basecast`, DMARC `_dmarc.basecast` with `p=none`). — The `*` record used to cover `basecast`; with names under it, a DNS wildcard may no longer match it (RFC 4592), so the explicit record keeps the app up. Do not delete it as redundant.
- 2026-09-26 — `/account` lets users change their own display name and photo, as in the Fundsys app: the app's first user writes (the kickoff had none). — Asked by the user.
- 2026-09-26 — Photos live in Postgres (`app."UserAvatar"`, bytea), not in GCS as in the Fundsys app: the browser crops them to 256×256, the route takes PNG, JPEG or WebP (checked by magic bytes) up to 1 MB, and `/api/users/[id]/avatar` serves them to signed-in users only. — A few dozen KB per user needs no bucket, no new IAM for `app-vercel` and no new Vercel env; a table apart from `User` keeps the bytes out of sign-in.
- 2026-09-26 — Name and photo URL ride in the JWT. After an edit the page calls `update()` and the `jwt` callback re-reads both from the database, never from the browser's payload; a `SessionProvider` seeded with the server session serves `useSession()` in the shell. — As in the Fundsys app: the menu and the page follow an edit at once, with no database read per page.
- 2026-09-26 — Every email goes out in one layout (`src/lib/email/layout.ts`), after the Fundsys and Upstate emails in the light-mode colors: forest band with the logo, lime rule, white card on the canvas cream, one lime button. `sendEmail()` takes content, not HTML, and escapes it; the logo is an inline CID PNG, not a hosted image. — Asked by the user; one layout keeps every email recognizable, taking content instead of HTML closes the door on unescaped input, and the inline logo shows before a deploy and without a request to our host (the proxy's auth gate, a client's network).
- 2026-09-26 — One standardized log for the app, get-data and airflow: table `ops.log` (Postgres `basecast`, schema `ops`), same columns and event names in all three (basecast-get-data data contract §7). Its DDL is the app's Prisma model `OpsLog` (`db push`); `prisma/ops-grants.sql` lets `basecast_writer` INSERT and gives `postgres` the reader role, for `etl_run`. — Asked by the user: everything in one Postgres table, read by one screen.
- 2026-09-26 — `/ops` reads `ops.log` and `etl_run` straight from Postgres (raw SQL through Prisma), not through get-data. — Left to me by the user; the screen that watches get-data has to work while get-data is down.
- 2026-09-26 — `/ops` is open to every signed-in user for now. — Asked by the user.
- 2026-09-26 — The app's logger is the Fundsys one, trimmed: one JSON line on stdout per call (`warn` on stdout, since Vercel files `console.warn` as an error), and from `info` up the same row goes to `ops.log` in `after()`, batched per instance; `debug` stays on stdout; a failed write never reaches the request. One `http.request` line per BFF request through `withSession`; healthy `/api/ops/*` requests are not stored. — Logging must not add latency or take a request down, and the screen's own 30 s polling would fill the log with itself.
- 2026-09-26 — Screen tabs use `<TabsList variant="line" color="brand">`, the Fundsys `color="emerald"` with BaseCast's accent: a new `brand` color in the Tabs component (line: the brand ink, forest in light and lime in dark; solid: the lime fill). /ops is the first screen with it. — Asked by the user: main tabs as in the Fundsys app, in the right accent.
- 2026-09-26 — `/data` is a mode, as the Fundsys Documents module: under `/data/*` the sidebar is swapped (by pathname) for the Data mode's own, with Overview, Tables, Pipeline runs, "Exit Data" and the bucket's folder tree. — Asked by the user ("look at how the Documents module does it").
- 2026-09-26 — Lake routes mirror the bucket path (`/data/lake/raw/source=ercot_gis/dt=2026-08-01/<file>`), with `=` left unescaped; a zip member, sheet and PDF page ride in the query (`?member=`, `?sheet=`, `?page=`). — Every folder and file gets its own link and tab, and the path reads like the gs:// URI.
- 2026-09-26 — The DataGrid is ported from components-app (English) with Fundsys's fixes and its server window (`useGridWindowQuery`, `grid-params`): blocks of 500 rows, total only with block 0, 100,000-row window. The BFF's `grid/` routes turn the grid's `f.<column>.<op>` params into get-data's `filter=column:op:value`. — The same contract as the Fundsys CNPJ grid, which the user asked for.
- 2026-09-26 — The BFF forwards only an allowlist of get-data paths (`src/lib/get-data/routes.ts`) and drops `content-length` from gzipped responses. — A catch-all with the token attached must not become an open proxy; `fetch` decodes gzip, so the compressed length would truncate the body.
- 2026-09-26 — PDFs render with react-pdf (pdf.js), loaded on demand, worker copied to `public/pdfjs/` on install, reading by HTTP Range through `/api/data/file`, which redirects to a signed GCS URL when get-data can sign one. — The Fundsys app's setup; the largest PDF in the lake is 78.5 MB.
- 2026-09-26 — The get-data client types are generated with openapi-typescript into `src/lib/api/get-data.d.ts` (`npm run api:generate`); requests go through one server-only `fetch` in `src/lib/get-data/client.ts`, with no runtime client library. — The BFF only forwards; the types are what the screens need.
- 2026-09-26 — `/data/flow` draws the dataset lineage with `@xyflow/react` and `@dagrejs/dagre` (the Fundsys workflow canvas's libraries), read-only, built in the browser from `/lake/sources`, `/tables` and `/pipeline/runs`; no new get-data endpoint. — Asked by the user; the three resources already carry sources → datasets, and dagre lays out the ~180 nodes in milliseconds.
- 2026-09-26 — Data health on the flow: the latest run decides first (running, failed, abandoned/partial = degraded); otherwise data is overdue when no update came 6 h after the next time its `schedule_cron` fires (America/Chicago); sources without a cron (manual) never go overdue. A table takes the worst health of its writer pipelines; an origin, of its sources. — Asked by the user (last update with a health icon on every card); the grace covers a run's own duration.
- 2026-09-26 — The map reads GeoJSON: `public/geo/tx-counties.geojson` (254 counties, `county_fips` as the `promoteId`) and `ercot-weather-zones.geojson`, generated by basecast-airflow `basecast export-geo` (A-M2); this supersedes the KICKOFF's TopoJSON. — Approved by the user; MapLibre reads GeoJSON natively (no `topojson-client`), and each file is under 1 MB before Vercel compresses it.
- 2026-09-26 — The product screens use the /data BFF catch-all and its allowlist, not a route handler per resource; their client side is `src/lib/bff/` (`fetchEnvelope`, `useProductQuery`). — Approved by the user; the BFF only forwards, and the catch-all already streams bodies with their headers (the accounts CSV needs no code), passes a 503 as it comes and logs each call with its `x-request-id`.
- 2026-09-26 — Caveat labels and texts come only from the API: `meta.caveats` on each response, and the `GET /caveats` catalog for the per-value badges ("Machine-read, not verified", "Simulated"). A 503 `mart_not_built` is an empty state in its own card; any other failure with nothing on screen goes to the route's `error.tsx`. — A required caveat never depends on someone writing it in the app, and a missing mart must not take the page down (BUILD B).
- 2026-09-26 — Accounts leads the menu and is the landing page (`/` and after sign-in). — Approved by the user; commercial intelligence is the core of the demo. `/insights` takes the top when it exists.
- 2026-09-26 — The app writes `ops.log` rows only on a deploy (`VERCEL_ENV` set) or with `OPS_LOG=1`; `OPS_LOG=0` turns them off anywhere. Locally the log stays on stdout. — A local `next start` used for UI checks reached production's `ops.log` through the Cloud SQL proxy in `.env` and wrote 242 rows of local traffic into /ops.
- 2026-09-26 — The Explorer map is MapLibre GL 6 (pinned) with the county polygons only: no basemap, no token, no glyph server. Colors go through `feature-state` keyed by `county_fips`, so a layer switch never reloads the geometry; the worker ships from `public/maplibre/` (copied on install) because its default URL is relative to a bundle the app's bundler moves. — KICKOFF/BUILD B allow "polygons only"; nothing external can fail during the demo.
- 2026-09-26 — Explorer colors follow the dataviz reference palette: channel as the hue (the first three categorical slots, the ones validated all-pairs for a choropleth) and the priority class as the lightness; magnitudes on the one-hue blue ramp with quantile bins; rank change on blue ↔ red with a grey midpoint; dark mode has its own steps. — The acquisition encoding is X14 §6's; quantile bins are display only, the ranks and classes come from the API.
- 2026-09-27 — Insights leads the menu and is the landing page, now that `mart_insights` is real; the cards keep the API's order (grade A shown larger), never re-sorted or numbered by the app. — The video opens there; the order changes as the remaining marts land.
- 2026-09-27 — Product screens move to the Fundsys dashboard look, /insights first: a page title in slate (`PageHeader`) instead of a card around the screen, one full-width card per finding stacked in the API's order under "Headline" (grade A, brand accent on the left edge) and "Supporting" headings, the `DashboardChartCard` header (icon tile, title, grey line, open link as an icon) and figures as Fundsys's `KpiItem`. — Requested by the user: the screens looked like a generic template; the stack also ends the ragged grid of cards with 1 to 8 figures.
- 2026-09-27 — /accounts follows Fundsys's CRM list (title with actions, one stat card per next action that filters the list, the table with no card around it) and /accounts/[id] its entity page (header, KPI strip, one tab per part with icons in the URL), each tab laid out on its own with charts where the data is a series. — Requested by the user: the diagnosis was one 4,700 px column of look-alike cards; tabs let each part take the layout its data needs.
- 2026-09-27 — /explorer follows the Fundsys dashboard look (layers as line tabs with icons, a labeled filter row, stat cards, cards with icon headers) and gains "Counties, ranked", the map as a table in the layer's order; the county panel stays beside the map (sticky), not in a sheet. — Requested by the user; the table is the map's table view (dataviz accessibility) and a faster way to reach a county; a sheet would cover the map and block clicking county after county.
- 2026-09-27 — The desktop breadcrumb title shows only a trail (two items or more); a one-item breadcrumb stays as the tab's name but is not drawn. — Requested by the user: every screen with a `PageHeader` showed its name twice, once as plain text above it.
- 2026-09-27 — Screens drop their excess text: no page subtitles, card subtitles only for data, definitions and one-card caveats behind an ⓘ (`InfoTip`), provenance once per screen as "As of {date}", caveats once per response, long API prose in tooltips or badges, empty states as a title, no internal names (marts, adapters, doc paths). Rules in CLAUDE.md "Screen text". — Requested by the user: the text-heavy screens read as AI-generated; an audit found ~350 prose items, most restating the title, legend or filters.
- 2026-09-27 — /backtest gets a scorecard above the tabs (peak MAPE vs LTLF and CDR, wins vs ERCOT by era, bias, band coverage vs 80%, queue rank ρ; orange where the model falls short) and a Models tab (every model and benchmark run, variants, dates, cells, leaks, the model builds), all from the existing contract. — Requested by the user: the screen showed the numbers but not whether the models are solid, nor what ran. The tab flags that the backtest scores "Latest deck" while /forecast defaults to "Before Batch Zero".
- 2026-09-27 — Each model run (mart build) opens as an audited notebook at `/backtest/runs/[runId]`, built from what `etl_run` already records (params, `mart.check` expected vs actual, `mart.built`, errors) read through get-data's `/tables/etl_run/rows`, with the unrecorded parts (config values, fit diagnostics, input freshness) shown as "Not recorded". What airflow must record and get-data expose next is in `docs/model-run-audit.md`, to move to get-data's decisions once a push there no longer redeploys the API mid-hackathon. — Requested by the user: audit each model run like a training notebook; layer A needs no contract change.
- 2026-09-27 — "Continue with Google" is open sign-up: any Google account with a verified email gets a user (never a superadmin) and every screen except the admin ones; admin is `isSuperAdmin`, checked in the database by `requireSuperAdmin` (404) and `withSuperAdmin` (403). No next-auth adapter: the `signIn` callback finds the user by Google id, else links a verified email to an existing user, else creates one (username from the email). An email already tied to another Google account is refused. Every superadmin is emailed on each sign-up. — Requested by the user: people watching the demo must be able to sign up on their own; staying adapter-free keeps JWT sessions and the one `User` table, and email linking lets `admin` use Google too.
- 2026-09-27 — The first admin screen is `/admin/users` (every account, how it signs in, role, sign-up and last sign-in; read-only), under an `/admin` layout that 404s non-superadmins, with its menu item hidden from them. Ops and Data stay open to every signed-in user. — Requested by the user, after Fundsys's users screen, to see who signed up with Google; the user chose to keep Ops open because the product is a full demo.
- 2026-09-27 — The two landing pages from Claude Design (product, "How BaseCast is built") are served as they came, static HTML in `public/landing/`, not ported to React: `/` rewrites to the product page for visitors (users still go to /insights), `/how-its-built` to the engineering page for everyone, with a floating toggle between them. The root's redirect moved from `next.config.js` to the proxy (config redirects run first and would hide the page). Their numbers stay hardcoded (lake counts as of Sep 26): the page is public and the BFF needs a session. — Requested by the user on the last build day; static keeps the design exact and loads no app bundle.
- 2026-09-27 — The home after sign-in (and `/` for a signed-in user, and "Exit Data") is `/home`, no longer `/insights`. — Requested by the user: signing in landed on Insights instead of Home.
